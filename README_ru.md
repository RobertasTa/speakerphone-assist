# Speakerphone Assist

![Speakerphone Assist — роботизированная рука держит спикерфон, связанный со значком Home Assistant (иллюстрация создана с помощью ИИ)](docs/banner.png)

**USB-спикерфон для конференций как голосовой спутник Home Assistant.** Говорите слово пробуждения, даёте команду
и слышите ответ. Официальная программа-спутник для Linux, правильно подключённая и настроенная, плюс то, что
трудно найти описанным: звук в контейнере Proxmox LXC, PipeWire без udev и своё слово пробуждения.

## Почему спикерфон для конференций

Спикерфон создан ровно для этой работы: массив микрофонов, слышащий всю комнату, аппаратное подавление эха,
громкий динамик и один USB-разъём (или маленький USB-радиоприёмник). Покупаете готовым — без пайки, без
микрофонных плат и без печати корпуса.

## Как это работает

```
спикерфон ──USB──► Linux (PipeWire) ──► Linux-Voice-Assistant ──протокол ESPHome, порт 6053──► Home Assistant
    ▲                                                                               (речь → текст → намерение → голос)
    └───────────────────────────── ответ голосом ◄──────────────────────────────────────────────┘
```

* **Linux-Voice-Assistant** (LVA) — официальная программа-спутник от Open Home Foundation (авторы
  пока называют её *экспериментальной*)
  ([OHF-Voice/linux-voice-assistant](https://github.com/OHF-Voice/linux-voice-assistant)). Слово пробуждения она
  слушает на самом спутнике, а с Home Assistant общается по протоколу ESPHome.
  Старый `wyoming-satellite` больше не развивается — новые установки на нём не начинайте.
* Остальное делает Home Assistant вашим конвейером Assist (распознавание речи, диалог, синтез голоса).

## Выберите путь

| Ваше оборудование | Что делать |
|---|---|
| Спикерфон подключён к компьютеру с **Home Assistant OS** | Официальное приложение **Assist Satellite** из [OHF-Voice/apps](https://github.com/OHF-Voice/apps). *Мы его не проверяли.* |
| Обычный компьютер с **Linux** (мини-ПК, ВМ, 64-битный Raspberry Pi) | Там PipeWire находит спикерфон сам — следуйте [официальной инструкции](https://github.com/OHF-Voice/linux-voice-assistant/blob/main/docs/install.md), а настраивайте как ниже. Наш `setup-lva.sh` создан и проверен для контейнеров. |
| **Proxmox** с контейнером LXC | Шаги 1–4 ниже. ✅ *Именно это мы проверили.* |

## Перед началом

1. **Только EMEET:** имя спикерфону задайте и прошивку обновите программой EMEETLINK **до** того, как подключите
   приёмник к серверу. Программа есть только для Windows и macOS и работает через USB-кабель.
2. **Узнайте ID карты.** Подключите спикерфон к компьютеру с Linux и выполните `arecord -l`:
   `card 2: A350 [EMEET Adapter A350], device 0: USB Audio` → ID карты — **`A350`**.
3. **У карты — один хозяин.** Спикерфон не должен использовать никто другой (сервер, другой контейнер, другая
   программа). Если кто-то его держит, PipeWire не запустится.

## Шаг за шагом (Proxmox LXC)

**1. Создайте контейнер** — шаблон Ubuntu 24.04, *unprivileged*, *nesting* включён, 2 ядра, 2 ГБ ОЗУ, 8 ГБ диска.
Оставьте его **остановленным**.

**2. На сервере Proxmox** дайте контейнеру звуковые устройства:

```bash
./pve-speakerphone-lxc.sh 120            # проба: показывает звуковые карты и что будет добавлено
./pve-speakerphone-lxc.sh 120 --apply    # записывает (сначала делает копию старого конфига)
```

В `/etc/pve/lxc/120.conf` он добавляет три вещи — доступ к устройствам ALSA (`c 116:*`), подключение `/dev/snd` и
**отображение группы `audio` (idmap)** — а в `/etc/subgid` соответствующую строку `root:29:1`. Без отображения
непривилегированный контейнер видит устройства как `nobody:nogroup` и не может их открыть.

**3. Внутри контейнера:**

```bash
./setup-lva.sh --card A350 --name gostinaya
```

Он устанавливает PipeWire и LVA, создаёт пользователя `lva`, **описывает спикерфон для PipeWire статически**
(см. «Неполадки» — в контейнерах нет udev) и запускает службу `linux-voice-assistant`.
Параметры: `--wake hey_jarvis` (слово пробуждения), `--user`, `--ref` (версия LVA).

**4. В Home Assistant:** *Настройки → Устройства и службы → Обнаружено → **lva-‹MAC-адрес›** (ESPHome) → Добавить.*
После добавления устройство получает имя, заданное через `--name`. Если ничего не обнаружено:
*Добавить интеграцию → ESPHome →* IP контейнера, порт `6053`.

## Настройка в Home Assistant

Всё — на странице устройства, файлы править не нужно.

| Настройка | Что делает | Наш совет |
|---|---|---|
| **Ассистент** (×2) | Какой конвейер Assist отвечает | Два слота: одно слово пробуждения может вести к английскому ассистенту, другое — к ассистенту на другом языке |
| **Слово пробуждения** (×2) | Встроенные: Okay Nabu, Hey Jarvis, Alexa, Hey Mycroft, Okay Computer, Hey Home Assistant, **Hey Luna**, … | «Hey Luna» подходит для EMEET Luna 🙂 |
| **Чувствительность слова пробуждения** | Порог распознавания (больше = строже) | Просыпается сама → увеличьте. Вас не слышит → немного уменьшите |
| **Громкость микрофона / автоусиление / шумоподавление** | Программная обработка перед словом пробуждения | Спикерфон уже очищает звук — начните с **выключенными** усилением и подавлением |
| **Определение конца речи** | Когда решает, что вы закончили говорить | *relaxed*, если обрывает; *aggressive* — для более быстрых ответов |
| **Выключение микрофона**, **звук «думаю»** | Микрофон выключен; звук во время ожидания | — |

Три вещи, которых на этой странице **нет**, но они важны:

* **Откройте устройства для Assist** (*Настройки → Голосовые ассистенты → вкладка «Expose»*). Иначе спутник поймёт
  вас прекрасно, а Home Assistant ответит, что доступа к устройству нет.
* **Самое медленное — распознавание речи, а не спутник.** В нашей проверке большая модель Whisper на процессоре
  тратила ~7 с на команду. Модель поменьше, GPU или *Speech-to-Phrase* для домашних команд — и ответ заметно быстрее.
  Для литовского: [LT_ausys](https://github.com/RobertasTa/lt-ausys) — около 0,2 с на команду на процессоре.
* **После сигнала говорите только команду.** Повторённое слово пробуждения станет командой.

Громкость динамика: громкость медиаплеера в Home Assistant и аппаратный уровень `alsamixer -c <ID карты>`
(регулятор `PCM`). Аппаратный уровень микрофона: регулятор `Mic` (на нашем экземпляре 85 %).

## Своё слово пробуждения («Okay Jenny», «Алиса», …)

LVA загружает каждый `*.json`, найденный в папках слов пробуждения; каждый появляется в списке слов пробуждения
Home Assistant. `setup-lva.sh` добавляет для ваших моделей папку `~lva/wakewords`. Два типа моделей:

```json
{ "type": "openWakeWord", "wake_word": "Okay Jenny", "model": "okay_jenny.tflite",
  "openWakeWord": { "probability_cutoff": 0.6 } }
```

```json
{ "type": "micro", "wake_word": "Okay Jenny", "model": "okay_jenny.tflite",
  "micro": { "probability_cutoff": 0.85, "feature_step_size": 10, "sliding_window_size": 5 } }
```

Положите `okay_jenny.json` и `okay_jenny.tflite` в `/home/lva/wakewords/`, выполните
`systemctl restart linux-voice-assistant` и выберите слово в Home Assistant. Модель должна быть **`.tflite`**.
Обучение openWakeWord (ниже) даёт модель первого типа; второй — для моделей microWakeWord.

**Как сделать модель.** Тетрадь обучения [openWakeWord](https://github.com/dscripka/openWakeWord) создаёт тысячи
синтетических голосов, произносящих вашу фразу, и обучает маленькую модель (около часа на GPU или в Colab).
Что мы измерили, обучая своё неанглийское имя:

* **Сначала проверьте произношение.** Сгенерируйте несколько образцов и пропустите их через распознавание речи. Для
  неанглийского имени голоса другого языка могут произносить его лучше: «Алису» по-литовски лучший русский голос произнёс
  правильно 12 из 12 (другие русские — гораздо хуже), английские — 0 из 20.
* **Одних синтетических голосов мало.** Наша модель узнавала синтетические образцы в 95–98 % случаев, а живого
  человека через спикерфон — лишь в 43–59 %. Добавьте 50–100 записей *своего* голоса, сделанных **через тот же
  спикерфон**.
* **Экзамен запишите до обучения**, например «не меньше 9 из 10 настоящих обращений, не больше 1 ложного пробуждения в
  сутки», и проверяйте на записях, которые в обучении *не участвовали*.

Просите помощи у ИИ-ассистента? Дайте ему [AI_CONSULTANT_BRIEF.md](AI_CONSULTANT_BRIEF.md) — там этот метод.

## Неполадки

| Признак | Причина и решение |
|---|---|
| PipeWire показывает только фиктивное устройство (`auto_null`) | В контейнерах нет udev, поэтому PipeWire не находит карту. `setup-lva.sh` добавляет статические узлы (`~lva/.config/pipewire/pipewire.conf.d/50-speakerphone.conf`). |
| PipeWire не запускается | Чаще всего карта занята — её держит кто-то другой. Смотрите `journalctl --user -u pipewire`. |
| Устройства в контейнере принадлежат `nobody:nogroup` | Не хватает отображения группы `audio` или строки в `/etc/subgid` — запустите `pve-speakerphone-lxc.sh` ещё раз. |
| `arecord`/`aplay` от root в контейнере пишет **«No such device»** | Устройство есть — root контейнера не входит в группу `audio`. Проверяйте от `lva`: `runuser -u lva -- arecord -l`. |
| «Доступ к … не предоставлен» / «not exposed» | Откройте устройство для Assist (см. выше). |
| `Failed to load cookie file` | Безвредно. |
| Динамик не принимает 16 кГц | Для EMEET это нормально (играет 48–96 кГц). PipeWire пересчитывает. |
| Вдруг «слышит» только шум, ошибок USB нет | Приёмник EMEET может зависнуть, не отключаясь. Выключите и снова включите спикерфон. |
| Глухой после того, как приёмник пропал с USB (`dmesg` показывает отключение и подключение USB) | Вероятно, звуковой сервер всё ещё держит старое устройство. Перезапустите его и спутник: `runuser -u lva -- env XDG_RUNTIME_DIR=/run/user/$(id -u lva) systemctl --user restart pipewire pipewire-pulse wireplumber && systemctl restart linux-voice-assistant`. Мы встретили это в своей (не LVA) системе со спикерфоном; с LVA не воспроизводили. |
| Два одинаковых спикерфона | Различайте по серийному номеру (`/dev/snd/by-id/`). ID карт (`A350`, `A350_1`) после перезагрузки могут поменяться — проще всего: один спикерфон на один контейнер. |
